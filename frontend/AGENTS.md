# AGENTS.md

## AI 快速执行摘要

- 先查真实调用链，再修改代码。
- 优先采用最小可行修改，只解决当前问题。
- 新增依赖、公共抽象或全局样式前，先确认确有必要。
- 默认保持轻量起步，不主动补齐 Pinia、Axios、mitt、工具函数库或工程化全家桶。
- 需要刷新后保留的路由参数优先使用 path params。
- 代码改动尽量运行语法、构建或类型相关校验；文档改动通常做 diff 检查即可。
- 任务完成后必须自review，并在回复中说明自查结果。

## AI 工作原则

- 修改前先阅读当前文件、关联组件、路由、API 和调用方，确认真实影响范围后再动手。
- 优先遵循项目已有目录结构、组件写法和命名风格。
- 不顺手重构、不扩展无关需求、不改变既有架构。
- 保护现有改动：不要回滚、删除或格式化与任务无关的文件，除非用户明确要求。
- 搜索和排查必须控制范围，优先查目标文件、同模块页面和必要公共组件，不扫描 `node_modules`、`dist` 等无关目录。
- 新增依赖前必须确认当前项目没有已有替代方案；能用轻量本地实现解决的小需求，不急着引入库。
- 公共工具、composable、store、request 封装只在出现真实复用或跨模块需求时新增。
- 修改后按影响范围做校验；代码改动尽量运行语法/构建检查，文档说明可只做人工 diff 检查。
- 每次任务完成后必须做一次自review，检查改动范围、潜在回归、是否满足用户最新要求，并在最终回复中简要说明。
- 回复保持简洁，说明改了什么、为什么改、是否校验；不要输出与任务无关的长篇解释。

## 项目说明

本项目是基于 Vue3 + Vite6 的轻量前端起步项目，使用 JavaScript 与 `<script setup>` 语法。默认只保留可运行的基础应用、路由首页、布局组件、全局样式变量和常用目录占位。

项目遵循“先轻量起步，按需扩展”的原则。不要一开始加入大量默认工具函数、请求封装、状态管理或工程化配置；只有业务真实需要时再添加。

## 技术栈

- Vue 3
- Vite 6
- JavaScript
- Vue Router
- SCSS
- unplugin-auto-import，仅自动导入 Vue API
- pnpm

## 包管理

- 优先使用 `pnpm`。
- 不使用 `npm` 或 `yarn` 安装依赖。
- 新增依赖前先确认是否真的需要，以及当前项目是否已有更轻的替代方案。
- 不要删除或随意重建锁文件。

## 目录规范

- `src/views/`：页面视图。新增页面时按 `src/views/xxx/index.vue` 组织，并在 `src/router/index.js` 配置路由。
- `src/components/`：公共组件。只有跨页面复用或职责明确的组件才放这里。
- `src/layout/`：布局组件，例如导航栏、页脚、应用外壳。
- `src/composables/`：组合式函数。只有可复用状态逻辑才放这里。
- `src/api/`：接口模块。需要接口请求时再新增具体 API 文件。
- `src/stores/`：状态管理。需要跨页面共享状态时再安装并使用 Pinia。
- `src/utils/`：公共工具函数。不要一开始生成一堆默认工具函数；确实复用时再沉淀。
- `src/assets/styles/`：全局样式和 SCSS 变量。
- `src/assets/images/`、`src/assets/icons/`：静态图片和图标资源。

## 默认不做的事

- 不默认安装 Pinia。
- 不默认安装 Axios。
- 不默认安装 mitt。
- 不默认生成 auth/token/cookie 示例。
- 不默认生成大量工具函数。
- 不默认生成 ESLint、Prettier、Husky、lint-staged；团队确定规范后再添加。

## 代码规范

- Vue 文件统一使用 `<script setup>`。
- 派生状态优先使用 `computed`。
- 布尔变量命名优先使用 `is`、`has`、`can`、`should` 开头。
- 多层对象访问使用可选链，避免运行时报错。
- 修改代码时优先遵循已有目录和写法，避免无关重构。
- 样式优先使用已有 SCSS 变量；响应式尺寸可使用 `clamp`、Grid `auto-fit` 和 `minmax`。
- 公共抽象只在确实减少重复或复杂度时新增。

## 路由与页面

- 页面路由集中维护在 `src/router/index.js`。
- 页面文件放在 `src/views/` 下。
- 需要刷新后保留的关键参数，优先使用 path params，而不是只依赖 query。
- 新增导航时，确保桌面端导航和移动端导航保持一致。

## API 与状态管理

- 需要请求接口时，再安装请求库并在 `src/api/` 与 `src/utils/request.js` 中组织。
- 消费接口前先确认响应结构，不要盲目假设字段。
- 只有多个页面或无直接父子关系组件共享状态时，才引入 Pinia。
- 单页面局部状态优先放在组件内或 composable 内。

## 修改与验证

- 修改前先阅读目标文件和相关调用链。
- 只实现当前需求，不顺手扩展无关功能。
- 不回滚用户已有改动，除非用户明确要求。
- 代码改动后尽量运行：

```bash
pnpm run build
```

如果只是脚本或局部 JS 文件，也可以先运行：

```bash
node --check 文件路径
```
